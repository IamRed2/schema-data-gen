# 의미 검색을 이용한 문맥 필드 선택

고정된 [한·영 필드 요청 24개](../../training/test/field-conditions.jsonl)로 문맥 선택 방식 네 가지를 비교한다. EXAONE 4.0 1.2B와 기존 프로젝트 LoRA, Intel Arc Vulkan, 현행 필드 프롬프트를 사용한다. 요청별 시드는 42와 123이다.

| 방식 | 모델에 주는 문맥 |
|---|---|
| 전체 | 현재 레코드의 모든 후보 |
| 키워드 | 영어 단어와 한국어 두 글자 조각이 많이 겹치는 후보 |
| 의미 검색 | Multilingual E5-small 코사인 유사도가 높은 후보 |
| 정답 선택 | 평가자가 필요한 것으로 지정한 키 |

키워드와 의미 검색은 같은 후보 키와 한·영 설명을 사용한다. 두 방식에 정답 필드 개수만큼 후보를 선택하게 해 순위 품질을 비교한다. 실제 사용에서는 이런 개수를 알 수 없으므로, 이 결과에 점수 임계값이나 선택 개수를 추정하는 성능은 포함되지 않는다. 후보 설명은 검색에만 쓰고 생성 모델에는 기존 키와 값만 전달해 선택 효과를 분리한다.

같은 요청과 시드에서 선택한 키까지 같으면 생성 결과를 공유한다. 조건별 지연 시간에는 이 공통 출력의 측정값을 사용하므로 각 방식의 독립 실행 총시간을 뜻하지 않는다. E5는 CPU에서 실행하고 같은 필드 설명과 후보 집합의 검색 결과를 캐시한다. 후보 수가 적어 벡터 DB는 필요 없다.

평가는 선택 집합의 정확 일치와 최종 문자열의 자동 조건 통과를 각각 계산한다. 자동 조건은 필수 표현과 혼동값을 확인하나 숫자의 역할이나 단위 의미까지 보장하지 않는다.

```powershell
. .training/xpu-venv/Scripts/Activate.ps1
py benchmark-results/semantic-context-v1/run.py
```

E5 가중치와 토크나이저는 `.training/multilingual-e5-small`에 배치한다. [E5 모델 카드](https://huggingface.co/intfloat/multilingual-e5-small)

용량 정리로 실험용 로컬 E5 파일을 삭제했다. 검색 실험을 다시 실행하려면 아래 결과에 기록한 리비전에서 가중치·설정·토크나이저를 복원한다.

## 결과

| 방식 | 필요한 필드만 정확히 선택 | 필요한 필드를 모두 포함 | 최종 출력 자동 검사 | 생성 중앙값 |
|---|---:|---:|---:|---:|
| 전체 문맥 | 0/24 | 24/24 | 24/48 | 0.998초 |
| 키워드 | 20/24 | 20/24 | 29/48 | 0.842초 |
| 의미 검색 | 14/24 | 14/24 | 19/48 | 0.849초 |
| 정답 선택 | 24/24 | 24/24 | 33/48 | 0.837초 |

평가 24건에서 검색 표현과 후보 집합이 고유한 경우는 12개였다. 나머지는 문맥의 값만 바꾼 쌍이다. 192개 조건별 출력에 실제 생성 요청은 116회였다. 캐시가 없는 CPU 검색 중앙값은 키워드 0.101ms, E5 26.624ms였다. E5 가중치는 약 471MB이고 모델 로딩은 1.878초였다. 이번 실험은 E5 리비전 `614241f622f53c4eeff9890bdc4f31cfecc418b3`을 사용했다.

키워드와 E5의 한국어 정확 선택은 각각 12/12와 8/12, 영어는 8/12와 6/12였다. E5는 한국어 청구서에서 미결제 금액 대신 이미 낸 금액을 골랐고, 구독에서는 요금제 이름 대신 기존 요금을 선택했다.

배송 8건씩의 최종 출력을 별도로 읽었고 네 방식 모두 기존 예상 대비 추가 소요를 정확히 알리는 문장은 0/8이었다. 정답 키를 넘겨도 상품이 도착했다고 쓰거나 추가 일수를 빠뜨렸다. 청구에서는 정답 키를 넘긴 경우에도 42달러를 42,000원으로 쓴 출력이 자동 검사를 통과했다. 따라서 필드 선택과 생성에서 값의 의미를 보존하는 능력을 별도로 개선해야 한다. 이번 결과는 검색 후보에 한·영 설명이 있고 선택할 개수가 주어진 조건에서의 비교다.
