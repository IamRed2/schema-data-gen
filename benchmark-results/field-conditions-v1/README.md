# 필드 설명의 조건과 문맥 반영 평가

- [IFEval](https://arxiv.org/abs/2311.07911)의 검증 가능한 지시 평가를 적용했다. 문자열 스키마, 언어 문자권, 필수 표현, 혼동하기 쉬운 값의 배제, 한 단어 형식을 각각 검사한다.
- [CheckList](https://aclanthology.org/2020.acl-main.442/)의 입력 변화 테스트를 적용했다. 도메인, 출력 언어, 필드명, 설명을 고정하고 관련 사실을 바꾼 두 요청을 짝지었다. 한 쌍의 두 출력이 모두 통과해야 해당 쌍을 통과한다.
- [ToTTo](https://aclanthology.org/2020.emnlp-main.89/)의 구조화된 입력 기반 문장 생성 방식을 적용했다. 관련 값은 `context`에 넣고, 설명으로 어떤 값을 골라야 하는지 지정한다. 기존 예약자 수, 기존 요금, 이미 결제된 금액처럼 의미가 다른 값을 같은 문맥에 넣었다.

외부 데이터 원문을 재사용하지 않고 예약, 배송, 구독, 재고, 시설, 청구 도메인에 맞게 한국어·영어 사례를 작성했다. [평가 데이터](../../training/test/field-conditions.jsonl)는 6개 도메인 × 2개 언어 × 2개 문맥 변형으로 24건이다. 정답 예문은 채점 규칙 확인용이며 모델 입력과 학습에 포함되지 않는다. 각 구성에서 시드 42와 123을 사용해 출력 48건과 문맥 쌍 24개를 평가한다.

```powershell
. .training/xpu-venv/Scripts/Activate.ps1
py benchmark-results/field-conditions-v1/run.py
```

동일한 Vulkan 실행기, 현행 필드 프롬프트, JSON 문자열 출력 제약을 사용한다. 시간은 모델 로딩 이후의 요청 시간을 합산한다. 문자권 검사는 한국어·영어 판별의 대용 지표다. 표현 일치 검사는 표기에 따라 정답을 놓칠 수 있으며, 숫자와 단어가 모두 등장해도 작성자 역할이나 사실의 의미가 틀릴 수 있다.

## 결과

| 구성 | 스키마 | 필수 표현 | 자동 조건 전체 | 문맥 쌍 | 생성 시간 |
|---|---:|---:|---:|---:|---:|
| EXAONE 1.2B + 프로젝트 LoRA | 48/48 | 31/48 | 24/48 | 9/24 | 52.13초 |
| Gemma 3 1B IT | 48/48 | 16/48 | 11/48 | 4/24 | 76.92초 |
| Qwen3.5 0.8B | 48/48 | 15/48 | 6/48 | 1/24 | 85.82초 |
| EXAONE 1.2B | 48/48 | 3/48 | 0/48 | 0/24 | 44.15초 |

EXAONE LoRA는 한국어 행사 안내에 정원을 반영했지만 시작 시각을 누락했다. 청구서에서는 42달러를 42,000원으로 바꾼 출력이 문자열 조건을 통과했다. Gemma의 통과 11건 중 8건은 한 단어 품목명이었다. `West Wing, 2, null`도 자동 조건을 통과했다. 이 점수는 문장 자연스러움이나 의미 정확도의 점수로 사용하기 어렵다.

후속 학습용으로는 평가와 겹치지 않는 도메인에서 액수와 통화, 정원과 예약자 수, 지연 일수와 도착 일수를 바꾼 한·영 예제 쌍을 보강할 수 있다. 모델 간 학습 효과를 비교하려면 같은 데이터와 학습 예산을 적용하고 이 세트를 다시 실행한다.

## 의미 검수

자동 조건을 통과한 41건을 다시 읽었다. 아래 기준을 모두 만족해야 바로 쓸 수 있는 값으로 판정했다.

1. **형식과 언어**. JSON 값으로 바로 저장할 수 있고, 요청한 언어와 형태로 작성됐다.
2. **필수 사실과 관계**. 필수 사실을 모두 담고, 숫자가 올바른 단위 및 역할과 연결된다. 예를 들어 달러 금액은 달러로 남아야 하고, 폐쇄된 층과 건물의 관계가 맞아야 한다.
3. **근거와 작성자 역할**. 입력에 없는 사실이나 약속을 추가하지 않고, 고객·상담원·운영팀 등 필드에 지정된 관점을 지킨다.
4. **완결성**. 품목명은 한 단어로, 안내문은 사용자가 바로 읽을 수 있는 문장으로 완성한다. 설명 복사와 필드에 대한 해설은 제외한다.

| 구성 | 자동 조건 | 검수 후 사용 가능 | 검수 후 문맥 쌍 |
|---|---:|---:|---:|
| EXAONE 1.2B + 프로젝트 LoRA | 24/48 | 14/48 | 3/24 |
| Gemma 3 1B IT | 11/48 | 8/48 | 4/24 |
| Qwen3.5 0.8B | 6/48 | 2/48 | 0/24 |
| EXAONE 1.2B | 0/48 | 0/48 | 0/24 |

Gemma의 통과 문맥 쌍 네 개는 전부 품목명이다. 이번 검수는 자동 통과 후보에 한정했고 평가자는 한 명이었다. 자동 탈락 중 동의어·숫자 표기 차이로 탈락한 정답을 복구하지 않았으므로, 수치는 전체 수동 평가 점수가 아닌 확인된 사용 가능 건수다.

검수 기록은 원본 출력의 SHA-256에 연결했다. 다시 생성한 출력에는 새 검수 기록이 필요하다.

```powershell
py benchmark-results/field-conditions-v1/review.py
```

## 다음 모델 비교에서 고정할 조건

- **백본 비교와 학습 효과 비교**. 프로젝트 LoRA를 적용하지 않은 체크포인트끼리 먼저 비교한다. 다음으로 각 백본에 같은 학습 예제, 데이터 순서, 스텝, 시드를 적용해 학습한 모델끼리 비교한다. 같은 백본의 학습 전후도 별도로 보고한다.
- **공통 실행 조건**. 평가 데이터와 시드, 프롬프트, 샘플링 설정, 양자화 수준과 GPU 실행기를 고정한다. 모델별 채팅 템플릿은 기록한다. 시작 시간과 준비 이후 요청 시간을 분리한다.
- **평가 순서**. 모델 이름을 가린 출력 전체를 같은 기준으로 판정한다. 자동 탈락도 확인해 동의어와 숫자 표기 변형을 구제한다. 경계 사례는 독립 검수 후 의견 차이를 기록한다. 환경 설정을 조정한 예제는 최종 평가 세트에서 분리한다.
- **비교 지표**. 사용 가능 건수와 두 변형을 모두 통과한 문맥 쌍을 기본으로 보고한다. 언어·도메인과 한 단어/문장별로 결과를 나누고, 같은 입력에서 어느 모델만 통과했는지와 처리 시간을 함께 보고한다. 여러 시드로 생성한 동일 요청은 별개 도메인 사례로 해석하지 않는다.
