# 레코드 기준값과 필수 사실 전달 실험

Qwen3-0.6B Q4와 `schema-value-context-lora.gguf`를 사용했다. 행사 안내, 전시실 안내, 상자 수령 안내를 한국어와 영어로 각 한 번 생성해 방식당 6건을 비교했다. 두 방식은 같은 스키마, 문맥, 시드로 모델에 안내문 하나를 요청했다. 계획을 추가한 방식에는 같은 문맥 값을 `plan.required_facts`로 한 번 더 제공하고 모든 값을 정확히 언급하도록 지시했다. 계획 작성에 모델 호출을 추가하지 않았다.

| 지표 | 기존 문맥 | 필수 사실 명시 |
|---|---:|---:|
| 문자열 스키마 통과 | 6/6 | 6/6 |
| 이름과 숫자 모두 등장 | 5/6 | 6/6 |
| 입력에 없는 숫자가 등장한 출력 | 0/6 | 1/6 |
| 호출당 평균 시간 | 3.59초 | 3.39초 |

이름은 대소문자를 무시한 문자열 일치, 숫자는 숫자열 일치로 집계했다. 한국어 전시 안내에서 계획을 추가하자 전시명과 전시실 번호를 완결된 문장으로 표현했다. 반면 한국어 수령 안내에는 입력에 없는 `3개`가 추가됐으며, 영어 수령 안내는 한 문장이라는 요구를 어겼다. 이름과 숫자의 등장 여부만으로 의미 일치나 문장의 자연스러움을 판정할 수 없다.

범위는 기준값이 고정된 안내문 생성이다. 레코드 전체의 계획 선택과 조립, 기준값의 다양성, 전체 레코드 처리량은 측정하지 않았다. 시간에는 호출마다 모델을 불러오는 비용이 포함되며 표본 6쌍으로 속도 개선을 판단하기 어렵다.
